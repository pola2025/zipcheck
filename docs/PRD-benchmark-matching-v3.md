## 1. 기획 의도 (절대 잃어버리면 안 되는 핵심)

### 원칙 1: 원가 ≠ 최저가
벤치마크는 "시장에서 가장 싼 제품"이 아니라 **해당 등급에서 실제로 사용되는 제품의 적정 시장가**여야 한다.

- 거실 펜던트 조명: 최저가 4만원이 아니라, 일반 아파트에서 쓰는 펜던트급 제품 15~50만원
- 비디오폰: 최하품 4만원이 아니라, 아파트 영상 비디오폰 18~30만원
- 아트월: 걸레받이 8천원/m이 아니라, 아트월 전용 벤치마크 150~250만/식

### 원칙 2: 일식 항목은 면적 역산하지 않는다
"욕실 1식", "아트월 1식"처럼 면적/수량을 알 수 없는 항목에 대해:
- ❌ 벤치마크 ㎡ 단가를 가져와서 면적을 추정하여 역산 → 터무니없는 편차 발생
- ✅ 해당 평수+등급의 **일식 적정 범위**와 총액을 직접 비교
- ✅ 범위 내 = 적정, 범위 초과/미달 = 주의/경고 (편차% 계산 불필요)

### 원칙 3: 벤치마크는 이미 있다, 매칭이 문제다
현재 405건의 벤치마크에 아트월(25만~120만/식), 싱크대 상판(20만~90만/m), 다운라이트(2.5만~8만/개) 등 세분화된 데이터가 있으나, 매칭 로직이 "같은 카테고리의 아무거나"를 가져오기 때문에 정확한 벤치마크를 못 찾음.

### 원칙 4: 비교 불가능하면 솔직히 말한다
매칭 실패, 단위 불일치, 정보 부족 등으로 **신뢰할 수 있는 비교가 불가능한 항목**은:
- 억지로 점수를 매기지 않는다
- "비교 불가 (정보 부족)" 으로 표시한다
- 해당 항목은 점수 산출에서 제외하되, 사용자에게 "이 항목은 별도 확인 필요"로 안내한다

## 3. 개선 설계

### 3.1 매칭 알고리즘 개선 (matchCategory + findBenchmark)

#### 3.1.1 matchCategory 개선

**현재**: substring 포함 → 순서 의존적
**개선**: 점수 기반 최선 매칭 (best-score matching)

```
1단계: category_mappings DB에서 후보 수집 (substring 매칭)
  → 복수 후보 허용 (현재는 첫 번째 매칭에서 즉시 return)

2단계: 각 후보에 점수 부여
  - exact match (항목명 완전 일치): 100점
  - category+item 양쪽 매칭: 80점
  - item만 매칭 (alias 포함): 60점
  - category만 매칭: 40점

3단계: 최고 점수 후보 반환

4단계: 후보 없으면 직접 카테고리 매칭 (기존 fallback)
  - 단, "철거" 키워드가 있으면 철거 우선 (하드 규칙)
```

**하드 규칙 예시:**
- "~철거", "~제거", "~해체" → 철거 카테고리 강제
- "~시공", "~설치", "~교체" → 해당 공종 카테고리
- "아트월", "포인트월" → 목공 카테고리

#### 3.1.2 findBenchmark 개선

**현재**: exact → 카테고리아무거나 → fallback
**개선**: std_item 부분매칭 추가 + 점수 기반 정렬

```
1단계: 정확한 매칭 (std_category + std_item exact + grade)
  → 현재 1차와 동일

2단계: 부분 매칭 (std_category + std_item substring/키워드)
  → "거실 아트월 시공" vs 벤치마크 "아트월" → 부분 매칭 성공
  → "주방 상판 교체" vs 벤치마크 "싱크대 상판" → "상판" 키워드 매칭
  → "LED 매입등" vs 벤치마크 "다운라이트" → 키워드 테이블 {"매입등": "다운라이트"}

3단계: 등급 fallback (같은 항목의 다른 등급)
  → 2단계에서 찾은 항목의 가장 가까운 등급

4단계: 카테고리 대표 벤치마크 (category default)
  → 카테고리별 "기본 항목" 지정 (현재처럼 아무거나가 아님)
  → 예: 바닥 기본 = 강마루, 목공 기본 = 몰딩, 전기 기본 = 콘센트교체

5단계: 매칭 실패 → null 반환 (억지 매칭 금지)
  → confidence = 0.2로 설정, 비교 불가 표시
```


```
    - 범위 상한 초과 10% 이내: score = 80 (약간 높음)
    - 범위 상한 초과 30% 이상: score = 40~20 (과다)
  → 범위 미존재 시:
    - confidence = 0.3
    - comparison_note = '비교 불가 (일식 범위 데이터 없음)'
```

3. 분석 파이프라인에서 일식 항목 감지 시 `evaluateLumpSum()` 호출
4. CATEGORY_COST_PROFILES 기반 역산 로직 제거 (일식에 대해서만)

### Phase 3: 벤치마크 보충 + category_mappings 확충 (0.5일)

1. 누락된 벤치마크 항목 추가:
   - 전기: 간접조명(m 단위), 펜던트조명(개), 비디오폰(식)
   - 주방: 수전(개), 싱크볼(개)
   - 기타: 청소/마무리(식), 현장관리비(식)
2. category_mappings에 하드 매핑 50건+ 추가

### Phase 4: 검증 (0.5일)

1. 김현우 견적 재분석 — 52점 → 목표 70~80점 범위
2. 나머지 3건 (박민수, 김철수, 이영희) 재분석
3. 편차 1000%+ 항목 0건 확인
4. 매칭 실패(confidence < 0.3) 비율 10% 이하 확인
