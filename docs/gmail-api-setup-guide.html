ZipCheck Gmail API 설정 가이드

hello@zcheck.co.kr에서 자동 메일 발송을 위한 OAuth2 설정

예상 시간: 15~20분 난이도: 중간

진행 체크리스트

1

Google Cloud Console 프로젝트 생성

  1. 1.
    console.cloud.google.com 접속
    Google Workspace 계정 (hello@zcheck.co.kr)으로 로그인
  2. 2.
    상단 프로젝트 선택 드롭다운 클릭 → "새 프로젝트" 클릭
  3. 3.
    프로젝트 이름: ZipCheck 입력 → "만들기"
  4. 4.
    생성 완료 후 해당 프로젝트가 선택되어 있는지 확인
이미 프로젝트가 있다면 기존 프로젝트를 사용해도 됩니다.
2

Gmail API 활성화

  1. 1.
    좌측 메뉴 → "API 및 서비스" → "라이브러리"
  2. 2.
    검색창에 Gmail API 검색
  3. 3.
    "Gmail API" 클릭 → "사용" 버튼 클릭
직접 링크로 이동 →
3

OAuth 동의 화면 설정

  1. 1.
    좌측 → "API 및 서비스" → "OAuth 동의 화면"
  2. 2.
    User Type: "내부" 선택 (Workspace 계정이므로)
    "내부"가 없으면 "외부" 선택
  3. 3.
    앱 정보 입력:
    • • 앱 이름: ZipCheck Mail
    • • 사용자 지원 이메일: hello@zcheck.co.kr
    • • 개발자 연락처: hello@zcheck.co.kr
  4. 4.
    범위(Scopes) → "범위 추가 또는 삭제" 클릭
    https://www.googleapis.com/auth/gmail.send
    검색해서 체크하거나, 수동으로 위 URL 입력
  5. 5.
    "저장 후 계속" 클릭하여 완료
"외부"를 선택한 경우: "테스트 사용자" 단계에서 hello@zcheck.co.kr을 추가해야 합니다. 게시(프로덕션)하지 않으면 테스트 사용자만 사용 가능합니다.
4

OAuth2 클라이언트 ID 생성

  1. 1.
    좌측 → "API 및 서비스" → "사용자 인증 정보"
  2. 2.
    상단 "+ 사용자 인증 정보 만들기" → "OAuth 클라이언트 ID"
  3. 3.
    애플리케이션 유형: "웹 애플리케이션"
  4. 4.
    이름: ZipCheck Gmail
  5. 5.
    "승인된 리디렉션 URI" 추가:
    https://developers.google.com/oauthplayground
  6. 6.
    "만들기" 클릭 → Client ID와 Client Secret이 표시됨

여기에 값을 기록하세요 (이 페이지에서만 사용, 서버로 전송되지 않음):

Client ID와 Secret을 안전한 곳에 메모하세요. 나중에 다시 확인할 수 있지만, Secret은 재생성해야 할 수 있습니다.
5

Refresh Token 발급

Google OAuth Playground를 사용하여 Refresh Token을 발급받습니다. 이 토큰으로 앱이 자동으로 메일을 보낼 수 있습니다.
  1. 1.
    OAuth 2.0 Playground 접속
  2. 2.
    우측 상단 톱니바퀴(Settings) 클릭:
    • • OAuth flow: Server-side
    • • Access type: Offline
    • • "Use your own OAuth credentials" 체크
    • • OAuth Client ID: Step 4에서 받은 Client ID 입력
    • • OAuth Client Secret: Step 4에서 받은 Client Secret 입력
  3. 3.
    좌측 "Step 1" 섹션에서 스코프 입력:
    https://www.googleapis.com/auth/gmail.send
    "Input your own scopes" 필드에 붙여넣기 → "Authorize APIs" 클릭
  4. 4.
    Google 로그인 화면 → hello@zcheck.co.kr 계정으로 로그인 → 권한 허용
    "이 앱은 확인되지 않았습니다" 경고가 나오면 → "고급" → "ZipCheck Mail(으)로 이동(안전하지 않음)" 클릭
  5. 5.
    "Step 2" 섹션에서 "Exchange authorization code for tokens" 클릭
  6. 6.
    Refresh Token이 표시됨 → 복사하여 아래에 기록
6

Cloudflare Workers 환경변수 설정

아래 명령어를 터미널에서 실행하거나, Cloudflare 대시보드에서 직접 설정합니다.

방법 A: wrangler CLI (터미널)

cd workers
echo "CLIENT_ID값" | npx wrangler secret put GMAIL_CLIENT_ID
echo "CLIENT_SECRET값" | npx wrangler secret put GMAIL_CLIENT_SECRET
echo "REFRESH_TOKEN값" | npx wrangler secret put GMAIL_REFRESH_TOKEN
echo "hello@zcheck.co.kr" | npx wrangler secret put GMAIL_SENDER_EMAIL

방법 B: Cloudflare 대시보드

  1. 1. dash.cloudflare.com → Workers & Pages
  2. 2. zipcheck-api 선택 → Settings → Variables
  3. 3. "Edit variables" → 아래 4개 추가 (Encrypt 체크)
변수명 값
GMAIL_CLIENT_IDStep 4의 Client ID
GMAIL_CLIENT_SECRETStep 4의 Client Secret
GMAIL_REFRESH_TOKENStep 5의 Refresh Token
GMAIL_SENDER_EMAILhello@zcheck.co.kr

위에서 값을 입력했다면 자동 생성된 명령어:

-- Step 4, 5에서 값을 입력하면 여기에 명령어가 자동 생성됩니다 --
7

테스트 발송

환경변수 설정 후 Workers를 재배포하고 테스트합니다.

# Workers 재배포
cd workers && npx wrangler deploy
# 테스트: 견적 제출 시 이메일이 발송되는지 확인
# 또는 Claude에게 테스트 API 호출을 요청하세요
설정 완료 후 Claude에게 "Gmail API 테스트 발송해줘"라고 요청하면 테스트 엔드포인트를 만들어 확인할 수 있습니다.

자주 발생하는 문제

Gmail token refresh failed

→ Client ID, Secret, Refresh Token 중 하나가 잘못됨. 값 앞뒤 공백/줄바꿈 확인.

Gmail send failed (403)

→ Gmail API가 활성화되지 않았거나, OAuth 동의 화면에서 gmail.send 스코프를 추가하지 않음.

Refresh Token이 만료됨

→ "외부" 앱이 테스트 모드이면 7일 후 만료. 앱을 "게시"하면 영구 토큰이 됩니다. 또는 "내부" 앱은 만료 없음.

"이 앱은 확인되지 않았습니다"

→ 정상입니다. "고급" → "이동" 클릭. 본인 앱이므로 안전합니다.

✓

설정 완료!

Gmail API가 정상적으로 설정되었습니다.

이제 견적 제출 시 hello@zcheck.co.kr에서 자동으로 확인 메일이 발송됩니다.
