1 견적분석 신뢰도 평가 5.5/10

A. 벤치마크 데이터 품질 CRITICAL

~90개 시드 벤치마크만 존재

마케팅 페이지의 "3,000건 데이터" 주장과 현실 사이에 큰 괴리. 카테고리별:

바닥
12건
주방
11건

10건
철거
7건 (중급만)

개선: 400건+ 확장 필요 (4등급 x 10카테고리 x 10항목)

findBenchmark() 6단계 폴백이 잘못된 비교 유발

auto-analysis.ts:495-538 — 같은 카테고리의 다른 항목 벤치마크로 대체 비교됨. 예: "원목마루" 고급 벤치마크가 없으면 "타일" 고급 가격으로 비교 → 완전히 잘못된 결과.

개선: 대체 사용 시 confidence 점수를 0.5 이하로 낮추고, 리포트에 "추정치" 표시

B. 스코어링 정확도 HIGH

marginRate = deviationPercent 개념적 혼동

auto-analysis.ts:766 — 벤치마크가 "시장가"인지 "원가"인지 모호. 시장가 대비 편차를 "마진율"로 표시하면 고객에게 오해를 줄 수 있음.

미매칭 카테고리에 기본 70점 (B등급) 부여

auto-analysis.ts:868-869 — 검증 불가 항목에 "대체로 합리적" 등급은 오해 유발. "검증 불가" 상태로 표시하고 점수 제외 필요.

등급 라벨이 "비쌈"/"저렴" 구분 못함

점수 30이 "매우 비쌈"으로 표시되지만, 실제로는 덤핑 위험(너무 저렴)일 수 있음. 양극단을 구분하는 라벨 필요.

적정가 범위 15-25%가 전 카테고리 균일 적용

시스템 자체 데이터(market-price-crawler.ts:129-140)에서 카테고리별 마진율이 다름: 철거 35%, 주방/가구 15%, 욕실 18%. 하지만 리포트는 모든 항목에 15-25% 표시.

C. 보정 계수 타당성 MEDIUM

지역 3단계(서울/경기/지방) 너무 단순

경기도 분당(고가)과 포천(저가) 동일 0.9x. 부산과 시골 동일 0.8x. 최소 5~6구간 필요.

등급 팩터 복합 효과: 프리미엄 + 성수기 + 독점 = 2.16x

팩터들이 곱셈으로 결합, 극단적 조합에서 비현실적 보정값. 팩터 간 독립성 가정이 틀림.

면적 팩터 50평에서 정체 (0.88)

70평, 100평도 동일 0.88x. 대형 시공의 추가 할인 미반영.

D. 고객 가치 평가 HIGH

협상 스크립트에 부정확한 가격 정보 포함 가능

벤치마크 미스매치로 계산된 "추정 원가"를 고객이 업체에 직접 발송 → 서비스 신뢰도 훼손.

분석 결과에 신뢰도/정확도 지표 없음

벤치마크 매칭된 비율, 대체 사용 비율, 데이터 신선도 등 표시 없음.

긍정 요소

  • 단위 불일치 감지 (면적 vs 일식) 자동 전환 — 우수한 설계
  • 투명성 보너스로 상세 견적서 인센티브 제공
  • 카테고리 원가 합산 폴백 — 묶음 항목에 대한 현명한 접근

3 코드 안정성 및 버그탐지 6.0/10

보안 이슈 (즉시 수정)

CRITICAL index.ts:34-46

CORS: 모든 origin 반사 — 마지막 줄 return origin이 어떤 도메인이든 허용. return null로 변경 필요.

CRITICAL quote-requests.ts:481-501

GET /by-phone/:phone 인증 없음 — 전화번호만 알면 모든 고객 데이터 조회 가능. 인증 미들웨어 또는 OTP 검증 추가.

HIGH db.ts:40-46

insertOne/updateOne 테이블명 비검증 — 현재 하드코딩이지만 SQL 인젝션 표면. 화이트리스트 추가.

HIGH index.ts:98-103

에러 핸들러가 내부 메시지 노출 — DB 에러 시 SQL 쿼리, 테이블명 노출. 프로덕션에선 제네릭 메시지 반환.

로직 버그

CRITICAL db.ts:75-88

transaction() 함수 작동 안 함 — Neon HTTP 드라이버는 요청 간 커넥션 공유 안 함. BEGIN/COMMIT이 각각 별도 커넥션. 현재 미사용이지만 함정.

HIGH auto-analysis.ts:693-696

Falsy 값 버그 — item.quantity || null에서 0이 null로 변환. ?? null로 교체 필요.

HIGH quote-requests.ts:733-838

auto-analyze 레이스 컨디션 — 중복 클릭 시 분석 2번 실행, 중복 레코드 생성. WHERE status NOT IN ('analyzing', 'completed') 가드 필요.

HIGH quote-requests.ts:402-452

알림이 응답을 차단 — "non-blocking" 주석이지만 실제로 await. waitUntil()로 변경 필요.

MEDIUM AnalysisResultView.tsx:1291-1307

비용 시뮬레이터 체크박스 충돌 — 모든 누락 카테고리가 같은 키(5000000) 공유 → 하나 토글하면 전부 토글.

MEDIUM AnalysisResultView.tsx:870

React Fragment key 위치 오류 — key가 Fragment 내부 tr에 있음. <Fragment key={idx}>으로 변경.

잘 된 부분

  • 모든 SQL 쿼리에 파라미터화 사용 ($1, $2) — SQL 인젝션 방어
  • 분석 아이템 배치 INSERT (20건 단위) — Workers 서브리퀘스트 제한 준수
  • JWT 인증에 crypto.subtle HMAC-SHA256 사용 — Workers 환경에 적합
  • 최종 점수 0~100 클램핑 — 음수/초과 방지
  • 패널티 캡 설정 (-12, -15) — 단일 이슈가 점수를 파괴하지 않음
