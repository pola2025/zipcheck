3-1. 견적서 파싱 알고리즘

입력 형식 감지 — 파일 확장자 + MIME 타입으로 파싱 전략 결정
테이블 구조 추출 — 행/열 감지, 헤더 식별, 병합 셀 처리
항목 필드 매핑 — 컬럼을 { category, itemName, qty, unit, unitPrice, total } 에 매핑
메타데이터 추출 — 고객명, 평수, 주소, 건물유형, 공사기간, 견적서 발행일, 업체명
검증 — 합계 교차검증 (항목 합 = 총액), 누락 필드 감지
에러 분류 — 파싱 실패를 두 유형으로 분리: parsing_error OCR 오독 | reasoning_error 분류 오류
Phase 1(수동): Claude가 파싱 → 사람이 검증 + 에러 유형 레이블링 + 발행일 수집
Phase 2(반자동): 스크립트 1차 추출 → AI 보정 → 사람 최종 확인

3-2. 항목 정규화 알고리즘 v1.2

입력: "LG하우시스 강화마루 12T 시공 (몰딩포함)"

  → ["LG하우시스", "강화마루", "12T", "시공", "몰딩포함"]

Step 2: 매핑 테이블 조회 (exact match)
  "강화마루" → { stdCategory: "바닥", stdItem: "강화마루" } ✅ HIT

Step 3: 매핑 실패 시 → 유사도 매칭
  Dash search_knowledge("강화마루") → 벡터 유사도 검색

Step 4: 매칭 실패 시 → 수동 매핑 요청
  사람에게 확인 → 매핑 테이블 저장
  → correctionReasonCode 선택 + 자유 텍스트 보충

Step 5: Gold Standard 속성 추출
  → brand: "LG하우시스"
  → grade: "중급"
  → feature_evidence: "LG하우시스 Z:IN 라인 → 중급 판정"  // NEW v1.2
  → bundled: true
  → components: ["마루시공", "몰딩시공"]

Step 6: 서브 카테고리 매핑
  대분류 "욕실" → 세부 공종: 방수, 타일, 도기, 배관

P1 단위 불일치 Hard Gate (v1.2 추가)

㎡ 단가와 "식" 단가를 가중치로 비교하는 것은 100% 무효. 단위 불일치는 가중치가 아니라 비교 자체를 차단하는 게이트로 작동.

// 비교 전 단위 검증 (Hard Gate)
if (customerUnit !== benchmarkUnit) {
  if (canConvert(customerUnit, benchmarkUnit)) {
    // 변환 가능: ㎡ ↔ 평, m ↔ cm 등
    customerPrice = convert(customerPrice, customerUnit, benchmarkUnit)
  } else {
    // 변환 불가: ㎡ vs 식, 개 vs LOT 등
    rating = "HIGH_UNCERTAINTY"
    comparisonBlocked = true
    // 리포트에 "단위가 달라 직접 비교 불가" 표기
    // De-bundling 시도 → 실패 시 수동 판단 요청
  }
}

3-6. 수량-면적 교차검증 P0 v1.6 신규

업체가 의도적으로 수량을 적게 산출(Under-Quantity)하여 초기 견적을 낮추는 "미끼" 전략 탐지. 공사 중 "추가 물량"으로 프리미엄을 청구하는 한국 시장 대표적 사기 수법.

// 수량-면적 교차검증 (v1.6 NEW)

// 카테고리별 표준 소요량 (34평 기준, 보정 가능)
standardQuantityPerSqm = {
  "바닥": { "마루/장판": 1.05, "타일": 1.10 },  // ㎡당 1.05~1.10 (로스율 5~10% 포함)
  "도배": { "벽지": 1.15 },                      // ㎡당 1.15 (벽면적 = 바닥면적 × 2.5~3)
  "페인트": { "도장": 1.10 }
}

// 검증 로직
expectedQuantity = property_size_sqm × standardQuantityPerSqm[category]
actualQuantity = original_quantity

// 판정
ratio = actualQuantity / expectedQuantity

if (ratio < 0.85) {
  // ★ 15%+ 부족: "과소산량" 경고
  flag = "UNDER_QUANTITY_WARNING"
  penalty = -8  // 종합 점수에서 감점
  report += "바닥재 수량이 실제 면적 대비 ${Math.round((1-ratio)*100)}% 부족합니다."
  report += "공사 중 추가 물량 요청으로 프리미엄 가격이 적용될 수 있습니다."
} else if (ratio > 1.25) {
  // 25%+ 초과: "과대산량" 주의 (패딩 의심)
  flag = "OVER_QUANTITY_WARNING"
  report += "수량이 표준 대비 높습니다. 로스율(Loss Rate)을 확인하세요."
}

"과소산량" 트릭 사례

34평(112㎡) 집에 바닥재 83㎡만 견적 → "나머지 29㎡는 현장에서 추가 물량" → 추가분은 단가 30~50% 할증 청구. 초기 견적만 보면 "저렴"하지만 최종 비용은 정상 견적보다 높음.

대응 (v1.6)

바닥/도배/페인트 카테고리에서 original_quantity와 property_size_sqm를 자동 교차검증. 15% 이상 부족 시 리포트에 "과소산량 경고" + -8점 패널티. 소비자가 계약 전 전체 물량을 확정하도록 안내.

Phase 1 적용: 관리자가 수동으로 수량 vs 면적 비교. Phase 2에서 자동화. 주의: 부분수리(특정 방만 시공)인 경우 false positive 방지를 위해 scopeType이 "부분수리"이면 검증 완화.

P0 v1.5 Global Conflict Hierarchy — 규칙 충돌 해결 계층

Case #5에서 만든 규칙이 Case #1의 규칙과 모순될 수 있음. "Master Rule overrides Local Rule" 계층 구조로 일관성 보장.

Conflict Hierarchy 스키마:

{
  "rulebook": [
    {
      "ruleId": "R-001",
      "scope": "GLOBAL",               // GLOBAL | CATEGORY | CASE_SPECIFIC
      "priority": 1,                    // 낮을수록 우선 (1 = 최고 우선순위)
      "rule": "브랜드 미기재 시 '중급' 기본 가정",
      "sourceCase": "GOI-001",
      "createdAt": "2026-02-04",
      "supersedes": [],              // v1.5: 이 규칙이 대체하는 이전 규칙 ID
      "conflictChecked": true        // v1.5: 기존 규칙과 충돌 점검 완료 여부
    },
    {
      "ruleId": "R-005",
      "scope": "CATEGORY",
      "category": "욕실",
      "priority": 2,
      "rule": "욕실 타일은 포세린 기준 중급, 수입 포세린 기준 고급",
      "sourceCase": "GOI-005",
      "createdAt": "2026-02-10",
      "supersedes": ["R-002"],       // R-002 규칙을 대체
      "conflictChecked": true
    }
  ]
}

GLOBAL (우선순위 1)

전체 카테고리에 적용되는 기본 규칙. 새 규칙 생성 시 GLOBAL 규칙과 충돌 여부 필수 점검.

CATEGORY (우선순위 2)

특정 공종에만 적용. GLOBAL과 충돌 시 GLOBAL 우선. 같은 카테고리 규칙 간 충돌 시 최신 규칙이 이전 규칙을 supersede.

CASE_SPECIFIC (우선순위 3)

특수 상황에만 적용 (예: 특정 브랜드의 예외). 상위 규칙과 충돌 시 상위 우선.

프로세스: 새 규칙 생성 → 기존 Rulebook 전체 검색(같은 scope) → 충돌 발견 시 supersede 처리 또는 scope 조정 → conflictChecked=true 후 저장.

HIGH 번들링 문제 (The "Bundling" Problem)

P1 NEW 숨겨진 현장 조건 (Hidden Site Conditions)

"현장 방문 후 확정" 조항이 포함된 저가 견적은 실제로 필수 구조 보수(하지 보수, 배관 노후 등)가 빠져 있는 거짓 벤치마크. 이를 Gold Standard로 저장하면 다른 정상 견적이 "비싸다"로 오판됨.

위험

"현장 후 확정" 견적 → 낮은 가격 → Gold Standard에 저가 벤치마크 생성 → 이후 정상 견적이 모두 "높음"으로 판정

대응 (v1.2)

hasPostVisitClauses 필드로 감지. 해당 항목은 벤치마크 가중치 0.5로 감소. 리포트에 "조건부 견적" 경고 표시.

P1 NEW 계절 인건비 변동 (이사철 프리미엄)

봄(3~5월)/가을(9~10월) 이사철에 인건비가 5~8% 상승. 10월 견적이 "높음"이라도 계절 보정 후에는 "적정"일 수 있음.

대응: Section 3-3의 seasonFactor 적용. quoteIssuedDate(발행일) 수집으로 자동 보정.

P0 v1.4 이사철 시차 (Moving Season Lag)

계절 보정은 현재 견적 발행일(quoteIssuedDate) 기준. 그러나 인건비는 착공월에 따라 결정됨. 2월 발행 → 4월 착공이면, 2월 비수기 가격이 아니라 4월 이사철 가격이 적용되어야 함.

위험

발행일 기준 seasonFactor 0.95(비수기) 적용 → 실제 착공은 이사철 → "적정"인 견적이 "비싸다"로 오판

대응 (v1.4)

constructionStartMonth 수집. 계절 보정 시 착공월 우선, 미정이면 발행월 폴백. 발행월 ≠ 착공월이면 리포트에 "계절 보정 주의" 표시.

P1 v1.4 자기선택 편향 (Self-Selection Bias)

분석 대상 견적서는 고객이 "의심스러워서" 제출한 것. 따라서 "의심스럽게 높은" 또는 "의심스럽게 낮은" 견적이 과대 표집되고, "평균/공정" 견적은 부족할 수 있음.

위험

Gold Standard에 극단값 편중 → "적정" 기준이 왜곡 → Phase 2 AI가 "평균" 견적을 판단 못 함

대응 (v1.4)

50건 축적 중 분포 모니터링: "양호/적정/약간높음/높음" 비율 추적. "적정" 사례가 20% 미만이면 의도적으로 "공정 견적" 수집 보완. 토브디자인 실행원가 데이터(173현장)를 "평균" 앵커로 활용.

P1 NEW 브랜드 등급 함정 (The "Premium" Brand Trap)

P0 v1.6 저가 덤핑 위험 (Under-Pricing Dump Risk)

한국 인테리어 시장에서 시장가보다 25%+ 저렴한 견적은 대부분 다음 중 하나: (1) 공사중단 후 추가금 요구, (2) 최저급 자재/인력 투입, (3) 필수 공정 생략. 과소 가격은 과대 가격보다 더 위험.

공사중단 리스크

저가 수주 → 자재비 부족 → 공사 중단 → "추가금 안 주면 철수" → 고객이 다른 업체에 높은 가격으로 이어 시공

품질 저하 리스크

견적서에 "LG Z:IN"이라 쓰고 실제로는 중국산 무브랜드 시공. 소비자가 공사 후 확인해도 이미 시공 완료.

추가 물량 트릭

수량 과소 산출 → 공사 중 "물량 부족" 통보 → 추가분은 단가 30~50% 할증. Section 3-6 교차검증으로 탐지.

대응 (v1.6)

비대칭 스코어링(Section 3-4): -25% 이하 → 30점 + "덤핑 위험" bracket. 리포트에 "이 가격대에서는 공사중단, 저품질 시공, 추가비용 리스크가 높습니다" 강력 경고. 소비자에게 "왜 이렇게 싼지 업체에 반드시 질문하세요" 액션 가이드 제공.

P0 v1.6 과소산량 트릭 (Under-Quantity Trap)

34평 집 바닥재를 25평분만 견적에 넣어 초기 가격을 낮추는 수법. 바닥을 뜯은 후 "나머지 9평은 추가 물량"으로 프리미엄 단가 청구.

위험

바닥 철거 후에는 다른 업체로 교체 불가능 → "포로 상태"에서 추가금 협상 → 전체 비용이 정상 견적보다 20~40% 더 높아짐

대응 (v1.6)

Section 3-6 수량-면적 교차검증: 바닥/도배/페인트의 original_quantity를 property_size_sqm와 자동 대조. 15%+ 부족 시 -8점 패널티 + "과소산량 경고" 리포트 포함.

P1 v1.3 Low-Ball Trap (미끼 견적 함정)

낮은 초기 견적은 대부분 "불완전"한 견적. 이 견적이 Completeness Score 없이 Gold Standard에 진입하면 공정한 종합 견적이 "비싸다"로 오판됨.

위험

completenessRating 1~2인 저가 견적 → 벤치마크 하향 왜곡 → 정상 견적이 "높음" 판정 → 사용자 오도

대응 (v1.3)

completenessRating 필수 기록. rating 1~2는 벤치마크 가중치 0.1~0.4로 대폭 감소. rating 1은 Gold Standard 제외 권고. 리포트에 "불완전 견적 주의" 표시.

P1 v1.5 "자재만" vs "턴키" 가격 함정 (Material-Only Trap)

일부 업체는 경쟁력 있어 보이기 위해 "자재만" 가격을 제시하고 인건비를 별도 협상으로 남김. missingCategories가 인건비 누락을 명시하지 않으면 completenessRating이 인위적으로 높아짐.

위험

"타일 자재 500,000원" (인건비 별도) → completenessRating 4로 평가 → Gold Standard에 저가 벤치마크 진입 → 자재+시공 포함 정상 견적이 "비싸다" 판정

대응 (v1.5)

MISSING_LABOR_[공종] / MISSING_MATERIAL_[공종] 분리 태그로 인건비·자재비 누락을 개별 식별. "자재만" 견적은 반드시 MISSING_LABOR_TILING 등으로 태깅. completenessRating 산정 시 인건비 누락이면 최대 3등급으로 제한.

P1 v1.5 아파트 단지 전속 프리미엄 (Apartment-Specific Premium)

한국 특정 아파트 단지에는 관리사무소에 높은 관리비를 납부한 "전속 업체"가 존재. 이 업체의 견적은 10~15% 높지만 숨겨진 편의(주차, 양중, 관리소 협조 등)가 포함되어 있음.

위험

전속 업체 견적을 일반 업체와 직접 비교 → 10~15% 높게 나옴 → "비싸다" 판정. 그러나 실제로는 양중비/주차비/관리소 협조비가 포함된 합리적 가격일 수 있음.

대응 (v1.5)

견적 메타데이터에 apartmentExclusiveContractor: boolean 필드 추가. true인 경우 regionFactor에 Apartment-Specific Premium (+10~15%)을 보정 계수로 적용. 리포트에 "단지 전속 업체 프리미엄 포함" 안내.

P0 v1.3 부가세(VAT) 불일치 리스크

한국 인테리어 견적서는 부가세 10% 포함/별도가 비일관적. isVatIncluded 없이 비교하면 10%의 체계적 오류가 50건 데이터셋 전체에 전파됨.

위험

VAT 포함 견적과 VAT 별도 견적을 그대로 비교 → 10% 편차 발생 → "약간높음"이 실제로는 "적정"인 경우 다수

대응 (v1.3)

isVatIncluded 불린 필드 필수 수집. VAT 별도(false) → 비교 전 ×1.1 정규화. 미확인(null) → 리포트에 "VAT 미확인 경고" + 벤치마크 비교 불확실성 표시.

미채택

실시간 일당(일당) 노임 인덱스 추적

감사 권고:

서울/경기 목수, 타일공의 실시간 일당 변동을 추적하여 인건비 벤치마크에 반영.

미채택 사유:

신뢰할 수 있는 실시간 데이터 소스가 없음. 대한건설협회가 노임단가를 연 1회 공시하며, 월간 변동 추적 가능한 공개 API/DB가 존재하지 않음. 비공식 시세는 편차가 크고 검증 불가. Master Price Pulse(v1.3)에서 연 1회 노임단가 공시를 이미 추적 중이므로, 현 단계에서는 이것으로 충분.

재검토 조건: 국토교통부/건설협회 API가 제공되거나, 자체 데이터 50건+ 축적 시 분기별 노임 변동 패턴 자체 추출 가능.

미채택

Top 3 인테리어 플랫폼 가격 비교 (오늘의집, 집닥 등)

감사 권고:

견적을 오늘의집, 집닥 등 플랫폼 평균가와 비교하여 소비자에게 시장 위치 제공.

미채택 사유:

해당 플랫폼의 가격 데이터에 합법적 접근 경로가 없음. 오늘의집/집닥은 견적 데이터를 공개하지 않으며, 크롤링은 이용약관 위반 + 법적 리스크. 또한 이들 플랫폼의 가격은 중개 수수료(10~15%)가 포함되어 있어, 직접 비교 시 왜곡 발생.

재검토 조건: 플랫폼과의 데이터 파트너십 체결, 또는 공개 가격 정보 API 제공 시.

"ZipCheck 보증" (최대 적정가 초과 시 무료 재검토)

감사 권고:

업체가 "최대 적정가" 이상 청구 시 무료 재검토를 제공하여 차별화.

미채택 사유:

코드/시스템 결정이 아닌 비즈니스 모델 결정. 기획서는 기술적 분석 시스템 설계 범위이며, 가격 보증 정책은 사업 전략/재무 분석 영역. 또한 벤치마크 데이터가 50건 미만인 현 단계에서 "보증"은 리스크가 크므로, Phase 2 이후 데이터 신뢰도 확보 후 사업부에서 별도 검토.

재검토 조건: Phase 2 진입(50건+) 후, 벤치마크 정확도 통계(MAE, MAPE) 확보 시 사업부 검토.

미채택

소방/방화 안전 항목 누락 탐지

감사 권고:

미채택 사유:

견적 분석 범위를 초과하는 설계 감리 영역. 소방 설비는 건축법/소방법에 따른 인허가 사항이며, 인테리어 견적서에 별도 기재하지 않는 것이 관행. 견적서에서 소방 항목의 유무로 견적 품질을 판단하는 것은 부적절. 다만, MISSING_FIRE_SAFETY를 missingCategories 태그 후보로 등록하여 향후 데이터로 판단.

재검토 조건: 실제 분석 데이터에서 소방 관련 분쟁 사례가 5건 이상 축적 시.

미채택 사유:

법률 자문 영역으로, 기술 시스템에서 법적 조언을 제공하면 책임 리스크 발생. 대신 "안전 결제 스케줄"(v1.6 P1)에서 10% 하자보수금 유치를 "권고 사항"으로만 안내하되, 법적 구속력 있는 계약서 조항은 전문 법률가 검토 필요로 안내.

재검토 조건: 법무 파트너십 체결 후, 검증된 계약서 템플릿을 제공할 수 있는 체계 구축 시.
